# Multi-Source Data Ingestion Plan

## Overview

Add four new data ingestion pipelines to SoakTrail, enriching each spring with campground proximity, near-city context, OSM/Wikipedia metadata, and CC-licensed images. All pipelines are idempotent Python scripts writing to SQLite, scheduled via cron.

---

## Phase 1: Recreation.gov Campgrounds

**Goal:** For each spring, find campgrounds within 10 miles and store name, distance, reservability, and link.

### API

Recreation.gov's internal search API (no auth required):
```
GET https://www.recreation.gov/api/search/campgrounds?latitude={lat}&longitude={lng}&radius=10&limit=20
```
Returns JSON with `campsites[]` array, each containing:
- `asset_name`, `asset_type` (Campground, RV Park, etc.)
- `latitude`, `longitude`
- `reservable` (boolean)
- `aggregate_cell_coverage` (1-5)
- `price_range`, `average_rating`
- `parent_asset_name` (managing entity, e.g. "Custer Gallatin National Forest")

### Script: `scripts/ingest_campgrounds.py`

1. Read springs from `springs.json` (or D1 export)
2. For each spring, query Recreation.gov API with lat/lng + 10mi radius
3. Calculate haversine distance to filter to true 10mi radius
4. Upsert into SQLite table `campgrounds`:
   - `spring_slug TEXT` (FK), `campground_name TEXT`, `asset_type TEXT`
   - `distance_mi REAL`, `reservable INTEGER`, `latitude REAL`, `longitude REAL`
   - `cell_coverage INTEGER`, `price_range TEXT`, `rating REAL`
   - `managing_entity TEXT`, `recreation_url TEXT`
   - `last_fetched DATETIME`
5. Idempotency: `INSERT OR REPLACE` on `(spring_slug, campground_name)`
6. Rate limit: 500ms delay between API calls

### Output Table
```sql
CREATE TABLE campgrounds (
  spring_slug TEXT NOT NULL,
  campground_name TEXT NOT NULL,
  asset_type TEXT,
  distance_mi REAL,
  reservable INTEGER DEFAULT 0,
  latitude REAL,
  longitude REAL,
  cell_coverage INTEGER,
  price_range TEXT,
  rating REAL,
  managing_entity TEXT,
  recreation_url TEXT,
  last_fetched DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (spring_slug, campground_name)
);
```

## Phase 2: SimpleMaps Near-City Pages

**Goal:** For each spring, find the nearest US city (by population) within 50 miles for "near-city" SEO pages.

### Data Source

SimpleMaps US Cities Basic v1.94 (CC BY 4.0):
- Download: `https://simplemaps.com/static/data/us-cities/1.94/basic/simplemaps_uscities_basicv1.94.zip`
- CSV columns: `city`, `city_ascii`, `lat`, `lng`, `state_id`, `state_name`, `county_fips`, `county_name`, `population`, `density`, `timezone`, `ranking`, `id`
- License: CC BY 4.0 — must link to `https://simplemaps.com/data/us-cities` on a public page
- ~31,257 rows, ~2-3 MB uncompressed

### Script: `scripts/ingest_cities.py`

1. Download and extract `uscities.csv` to `data/uscities.csv`
2. Load all 31K cities into memory (small enough)
3. For each spring, find nearest city within 50mi using haversine
4. Also find nearest city per state for each region
5. Upsert into SQLite table `near_cities`:
   - `spring_slug TEXT`, `city_name TEXT`, `state_id TEXT`
   - `distance_mi REAL`, `population INTEGER`, `density REAL`
   - `latitude REAL`, `longitude REAL`, `ranking INTEGER`
   - `near_city_slug TEXT` (generated: `{city}-{state}` for URL)
6. Generate near-city pages data as JSON export

### Output Table
```sql
CREATE TABLE near_cities (
  spring_slug TEXT NOT NULL,
  city_name TEXT NOT NULL,
  state_id TEXT NOT NULL,
  distance_mi REAL,
  population INTEGER,
  density REAL,
  latitude REAL,
  longitude REAL,
  ranking INTEGER,
  near_city_slug TEXT,
  last_fetched DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (spring_slug, city_name, state_id)
);
```

### Near-City Pages

Add `src/pages/near/[slug].astro` route to each child site:
- Page title: "Hot Springs Near {City}, {State}"
- Shows springs within 50mi of that city
- Includes city population, distance to each spring
- SimpleMaps attribution footer: "City data from SimpleMaps (CC BY 4.0)"

## Phase 4: OSM Overpass + Wikipedia/Wikidata

**Goal:** Enrich springs with OpenStreetMap metadata (access tags, amenities, descriptions) and Wikipedia/Wikidata content (descriptions, history, CC images).

### 4a. OSM Overpass API

**API:** POST to `https://overpass-api.de/api/interpreter`
```
[out:json];
node["natural"="hot_spring"]({south},{west},{north},{east});
out body;
```

**OSM tags of interest:**
- `name`, `alt_name`, `old_name`
- `natural` = hot_spring
- `access` = yes/no/PRIVATE/permit
- `fee` = yes/no
- `opening_hours`
- `amenities` (surrounding nodes)
- `website`, `wikipedia`, `wikidata`
- `ele` (elevation)
- `description`, `note`

### 4b. Wikipedia API

**API:** `https://en.wikipedia.org/w/api.php`
```
?action=query&titles={page_title}&prop=extracts|pageprops&exintro=true&format=json
```

Also: `prop=images` for CC images on the Wikipedia page.

### 4c. Wikidata SPARQL

**API:** `https://query.wikidata.org/sparql`
```sparql
SELECT ?spring ?springLabel ?description ?image ?coordinates WHERE {
  ?spring wdt:P31/wdt:P279* wd:Q177374 .  # hot spring
  ?spring wdt:P625 ?coordinates .
  OPTIONAL { ?spring schema:description ?description . FILTER(LANG(?description) = "en") }
  OPTIONAL { ?spring wdt:P18 ?image . }
  SERVICE wikibase:label { bd:serviceParam wikibase:language "en" . }
}
```

### 4d. Wikimedia Commons API

**API:** `https://commons.wikimedia.org/w/api.php`
```
?action=query&generator=search&gsrsearch={spring_name}+hot+springs&gsrnamespace=6
&prop=imageinfo&iiprop=url|extmetadata&format=json
```

Returns images with `LicenseShortName` (CC BY-SA, CC BY, PD, etc.) and `AttributionRequired`.

### Script: `scripts/ingest_osm_wiki.py`

1. **OSM Pass:** For each spring, query Overpass API by bounding box (±0.5° around lat/lng)
   - Match by name similarity or coordinate proximity
   - Extract OSM tags into structured data
2. **Wikidata Pass:** SPARQL query for all US hot springs with coordinates
   - Match to existing springs by coordinate proximity (<0.01° ~1km)
   - Extract: `description`, `image`, `inception` date, `heritage status`
3. **Wikipedia Pass:** For matched Wikidata items, fetch Wikipedia extract
   - Extract first 2-3 paragraphs as description
   - Check for infobox image
4. **Wikimedia Commons Pass:** Search Commons for images
   - Filter to CC-licensed images only (CC BY, CC BY-SA, CC0, PD)
   - Store URL, license, attribution text
5. Upsert into SQLite tables

### Output Tables
```sql
CREATE TABLE osm_metadata (
  spring_slug TEXT PRIMARY KEY,
  osm_node_id INTEGER,
  osm_name TEXT,
  osm_access TEXT,
  osm_fee TEXT,
  osm_opening_hours TEXT,
  osm_elevation REAL,
  osm_website TEXT,
  osm_wikipedia TEXT,
  osm_wikidata TEXT,
  osm_description TEXT,
  osm_tags TEXT,  -- JSON blob of all tags
  last_fetched DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE wiki_content (
  spring_slug TEXT PRIMARY KEY,
  wikipedia_title TEXT,
  wikipedia_extract TEXT,  -- first 2-3 paragraphs
  wikidata_description TEXT,
  wikidata_image_url TEXT,
  wikidata_inception TEXT,
  wikidata_heritage TEXT,
  last_fetched DATETIME DEFAULT CURRENT_TIMESTAMP
);

CREATE TABLE wiki_images (
  spring_slug TEXT NOT NULL,
  image_url TEXT NOT NULL,
  image_source TEXT,  -- 'wikimedia_commons' or 'wikipedia'
  license_code TEXT,  -- 'CC BY-SA 4.0', 'CC BY 4.0', 'PD', etc.
  attribution TEXT,
  description_url TEXT,
  is_primary INTEGER DEFAULT 0,
  last_fetched DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (spring_slug, image_url)
);
```

## Unified Architecture

### File Structure
```
scripts/
  ingest_campgrounds.py    # Phase 1: Recreation.gov
  ingest_cities.py         # Phase 2: SimpleMaps
  ingest_osm_wiki.py       # Phase 4: OSM + Wikipedia + Wikidata + Commons
  lib/
    haversine.py           # Shared distance calculations
    db.py                  # SQLite connection + schema init
    rate_limit.py          # API rate limiting
data/
  uscities.csv             # Downloaded SimpleMaps data
  soaktrail.db             # SQLite database
```

### Database Schema (combined)
All four scripts share `data/soaktrail.db` with tables:
- `springs` — core spring data (from existing seed scripts)
- `campgrounds` — Phase 1 output
- `near_cities` — Phase 2 output
- `osm_metadata` — Phase 4a output
- `wiki_content` — Phase 4b-c output
- `wiki_images` — Phase 4d output

### Scheduling
- **Campgrounds:** Weekly (Recreation.gov data changes slowly)
- **Cities:** One-time download, re-run if SimpleMaps updates
- **OSM/Wiki:** Bi-weekly (OSM edits are infrequent)

### Integration with Astro Sites

1. **Spring detail page** (`[slug].astro`): Add campground card + near-city card + image carousel
2. **Near-city pages** (`/near/[slug].astro`): New route showing springs near a city
3. **Attribution**: SimpleMaps CC BY 4.0 link in footer, Wikimedia Commons attribution on images
